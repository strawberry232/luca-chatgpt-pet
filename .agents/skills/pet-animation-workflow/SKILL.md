# 宠物动画制作与修复

以用户认可的角色画面为造型基准，制作可复查的动作，交付符合目标宿主格式的素材。沿用项目已有制作方式，依照当前请求和会话中已有授权继续，不重复征求已有授权。技能本身不扩大重画、改名、切换宠物或公开投稿的范围。

## 确定改动

- 找到工作项目、认可的原图/图集、目标动作、实际宿主。只有宿主不明确且影响交付时才询问；不要将 ChatGPT 图集任务改成桌面 Live2D 工程。
- 查看待机参考和本次动作预览，记录颜色、衣服形制、条纹方向/宽度、左右眼、配件与身体左右侧。区分解剖学左右与画面左右。
- 保留改动前图集，明确可修改的行。普通动作修复无需重生成已经认可的其他表情和注视方向。

## 选择制作方式

编辑或生成原画时使用可用的图像技能及其要求。有合适侧面原画时复用；没有侧面而用户要求完整侧身时，先补出与原图一致的侧面，再制作循环。对称部位可以镜像，单眼颜色、绷带、配件等非对称特征单独处理。

当用户选择拆层/手工绑定，或项目已授权这一方式时，固定侧面纹理并制作分层关节动画。不要将纯正面摆腿称为完整侧身，不要逐帧独立重画造成条纹和配色漂移。没有该方式授权时，遵循当前 Pets 创作技能限制，不将本项目的历史授权推广到新任务。

修复跑步、配色和遮挡时读取 [animation.md](references/animation.md)。处理卢卡项目时再读取 [luca-project.md](references/luca-project.md)；其中颜色、坐标和素材只是本角色的实例。

## 验收与交付

- 查看原尺寸循环、放大关键帧和两个方向，检查接地、腾空、摆臂、膝踝关系、遮挡及边缘。与待机并排对照。配色按材质校准一次，不逐帧全局调色，不给远腿统一染暗代替遮挡。
- 区分客观检查与观感：尺寸、透明度和逐像素保留可用脚本证明；脚本不能证明动作自然、衣服语义正确或所有材质颜色一致。
- 检查图集、版本或投稿包时读取 [atlas-and-petdex.md](references/atlas-and-petdex.md)。随技能提供的 `scripts/pet_assets.py` 仅依赖 Python 和 Pillow，支持 `inspect`、`compare`、`package`，用 `--help` 查看参数。项目路径从本次上下文确定，不能假定技能安装目录就是素材项目。
- 交付最终图集、相关动作预览、制作源文件/参数及检查结论。需要 Petdex 投稿时输出带 `pet.json` 的 ZIP；按用户要求同步中英文说明。

## 宿主与权限

在 ChatGPT 创建、更新或管理宠物时，使用当前可用的 `work-pets:create-pet`、`work-pets:update-pet` 或 `work-pets:pets` 技能和 Pets 工具。复用已确定的稳定宠物 ID，更新前验证最终图集。上传成功不等于已启用，不为动画修复切换当前宠物。

“制作投稿包”只生成本地文件，仅在用户要求发布/投稿时执行外部提交。保持已有 GitHub 可见性，不将账号宠物记录、签名 URL、登录材料或本机绝对路径放入公开包。

九种动画不等于九条可手动触发的指令。客户端映射缺少文档支持时说明未知，尤其不能保证发送“检查成果”就播放 `review`。先报告真实交付和检查结论，再说明仍需视觉预览或宿主确认的部分。
