# 宠物制作：最小完整流程

先沿用用户选定的宿主、素材与制作方式。在 ChatGPT 创建、更新或管理宠物时，先使用对应的现有 Pets 技能，遵循其必需步骤；本技能补充造型与动作经验，不重复实现上传流程。只改名称或说明时走元数据更新，不重做图片。

**保持跨动作造型一致。** 所有动作基于同一份已确认的角色基准，保持脸型、头身比例、发型、配色、服装结构、图案及标志性细节一致。允许符合角色结构的姿态、表情、透视和遮挡变化，不将这些变化画成外观漂移；用户明确要求改造型时按新要求更新基准。修复单个动作时保留其他已确认动作。

## 1. 确定基准

有认可原图就直接复用；新角色先固定一张造型，再做必需状态。更新已安装宠物时下载当前图集作为本次基准，不拿旧仓库覆盖新宠物。确认头型、发色、衣服、左右特征及本次目标动作；项目专属约定读项目说明，不写成通用规则。

## 2. 只制作缺少或要修的动作

保留已通过的状态。需要补画时用现有图像生成/编辑技能；可复用认可帧或只需裁切、拼图时，不重新生成。已有拆层授权时复用固定纹理做关节动画，缺侧面先补侧面；非对称眼睛、绷带等不能直接镜像换侧。跨动作一致性、步态或遮挡问题再读 [animation.md](references/animation.md)。

不自动增做网页、鼠标追踪、转向补帧或独立播放器，也不因修一个动作而反复重画整张图集。

## 3. 检查真正的交付结果

从最终图集导出所需预览，检查动作衔接、头部大小、配色、衣服、接地和透明边缘；修复时逐行比较，确认非目标行未变。宿主规定的完整验收照常完成；复用未变内容的有效结果，不为同一文件反复运行相同检查。

眨眼等速度先确认宿主能否控制逐帧时长。快 GIF 不代表原生播放已提速；没有触发接口也不能承诺关键词触发动作。不要为普通制作默认检查客户端源码。

图集布局、版本或 Petdex 打包问题再读 [atlas-and-petdex.md](references/atlas-and-petdex.md)。可复用 `scripts/pet_assets.py` 的 `inspect`、`compare`、`package`；它不替代宿主验证或视觉判断。

## 4. 按需同步与交付

展示动作并验证实际要上传的文件；文件改变后重新验证。用户要求同步时更新同一个宠物 ID，保留当前选择；回读核对后把正式文件用于仓库和投稿包。平台可能重新编码 PNG，需区分字节相等与 RGBA 像素相等。失败时保留已通过的本地成果，不反复创建宠物。

默认交付最终图集、必要预览和可复用源文件；ZIP、GitHub、中英文说明按用户要求提供。旧稿、调试输出留本地，不混入正式交付。不把制作或打包当作公开发布授权；沿用会话已有授权，不重复征求相同许可。
